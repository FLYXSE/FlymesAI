# FlymesAI — Telegram Serverless AI bot

AI-бот на [Telegram Serverless](https://core.telegram.org/bots/serverless), открытый для всех: **каждый пользователь работает на своём AI-агенте**.

- общается через любой OpenAI-совместимый endpoint — **пользователь сам задаёт BASE_URL и API_KEY**;
- ключ хранится в БД зашифрованным (AES-256-GCM, см. `tgcloud/lib/crypto.js`);
- обязательная подписка на канал [@FLYXSE_README](https://t.me/FLYXSE_README);
- держит контекст диалога в базе платформы (таблицы `chats` и `messages`);
- отвечает **rich messages** (`sendRichMessage`) с заголовками, таблицами, кодом и формулами;
- стримит ответ в личке через `sendRichMessageDraft` (эффект «печатает»);
- оформлен **premium-эмодзи** из набора [Telegram iOS Icons](https://t.me/addemoji/tgiosicons) (173 иконки в `tgcloud/lib/emoji.js`);
- умеет работать в **Guest Mode** — по упоминанию `@FlymesAI` в любом чате;
- под guest-ответом ставит разделитель и две кнопки по центру: **README.md** и **Запрос**;
- в guest-ответе показывает служебную строку: модель, провайдер, время ответа, скорость и токены;
- даёт выбрать модель и **добавлять/удалять модели** прямо в боте — список свой у каждого.

## Как это работает

**Первый вход.** `/start` → бот проверяет подписку на [@FLYXSE_README](https://t.me/FLYXSE_README). Нет подписки — экран с кнопками «Открыть канал» и «Я подписался». Есть — просит настроить агента:

1. **BASE_URL** шлюза (например `https://api.openai.com/v1`);
2. **API_KEY** — бот сразу удаляет сообщение с ключом из чата, проверяет связку запросом `GET /models` и шифрует ключ;
3. список моделей из ответа шлюза становится личным списком, первая — активной.

Дальше — обычный диалог. Перенастроить агента можно командой `/agent`.

**В группах** бот отвечает автором сообщения его же агентом; история — общая на чат. Неподписанным в группе бот молчит, чтобы не спамить.

**В Guest Mode** нужны подписка и настроенный агент. Если чего-то нет — единственный разрешённый ответ содержит подсказку со ссылкой в личку.

```

│  ├─ agent.js           # нормализация BASE_URL + проверка ключа
│  ├─ subscription.js    # проверка подписки с кэшем
│  ├─ onboarding.js      # диалог настройки агента
│  ├─ ai.js              # запросы к AI (buffered + SSE)
│  ├─ generate.js        # стриминг драфтов + финальный rich message
│  ├─ chatflow.js        # вопрос/ответ и /retry
│  ├─ repo.js            # история диалога в БД

```

## Доступ

Три уровня:

| Уровень | Кто | Что |
|:--|:--|:--|
| Админ | `ADMIN_IDS` в `config.js` (969434663) | проходит без подписки, агент засеян из конфига |
| Подписчик | любой, кто подписан на [@FLYXSE_README](https://t.me/FLYXSE_README) | полный доступ после настройки агента |
| Остальные | — | экран подписки в личке, молчание в группах |

Проверка подписки идёт через `getChatMember` — **бот должен быть админом канала**, иначе Telegram не отдаёт статус других пользователей. Результат кэшируется на 5 минут (`SUBSCRIPTION_TTL_MS`); сбой API подписку не выдаёт (fail-closed) и не кэшируется.

## Команды бота

| Команда | Что делает |
|:--|:--|
| `/start` | приветствие (rich message с блоками и кнопками) |
| `/help` | справка с личным списком моделей |
| `/new`, `/reset`, `/clear` | очистить контекст |
| `/retry` | сгенерировать последний ответ заново |
| `/model` | список моделей и переключение (только в личке) |
| `/model add <id>` | добавить модель в список |
| `/model del <id>` | убрать модель из списка |
| `/agent` | перенастроить BASE_URL и ключ |
| `/cancel` | отменить ввод |
| `/id` | показать chat/user id |

### Модели

Модели хранятся в `users.models` (JSON-массив id) — свой список у каждого.

- **Кнопка «⚙️ Модель»** → список моделей; внизу «➕ Добавить» и «🗑 Удалить».
- «Добавить» просит прислать id одним сообщением (латиница, цифры, `. _ : / -`, до 60 знаков).
- Удалить последнюю модель нельзя.
- Если убрали активную модель, бот откатится на первую из оставшихся.
- В группах модель не переключается: бот присылает кнопку «Открыть личку».

## Premium emoji

Все иконки — из набора `tgiosicons`, карта лежит в `tgcloud/lib/emoji.js`:

```js
import { md, block, plain } from './emoji.js';

md('sparkles')    // ![✨](tg://emoji?id=…)  — внутри markdown
block('check')    // { type: 'custom_emoji', … } — внутри blocks
plain('gear')     // '🔧' — обычный глиф: таблицы, fallback
```

Правило: **в markdown — `md()`, в блоках — `block()`, в таблицах и текстовых fallback'ах — `plain()`**. Перепутать `md()` и `block()` нельзя: в блоках строка `![…](tg://…)` отрендерится как обычный текст.

Все 173 пары проверены против живого `getStickerSet('tgiosicons')`. Если набор изменится, эмодзи откатится к обычному глифу, а сообщение останется валидным.

## Деплой

```bash
cp tgcloud/lib/config.example.js tgcloud/lib/config.js   # затем вписать свои значения
npx tgcloud login     # токен: BotFather → бот → Serverless → CLI Access
npx tgcloud status
npx tgcloud push
npx tgcloud migrate   # только при изменениях schema.js
```

`tgcloud/lib/config.js` не хранится в репозитории: в нём ключ шлюза и `MASTER_SECRET`. Шаблон с теми же экспортами — `config.example.js`.

Порядок при изменениях схемы: сначала `migrate --local --safe` (создание таблиц), перенос данных, потом дроп колонок (`--local --yes`) — `migrate` удаляет данные без возможности отката.

Тест без деплоя:

```bash
npx tgcloud run handlers/message '{ message_id: 1, chat: { id: 969434663, type: "private" }, from: { id: 969434663, first_name: "Owner" }, text: "/start" }'
```

## Чек-лист в @BotFather

1. **Serverless** — включён.
2. **Guest Chat Mode** — включён (упоминание бота в чужом чате).
3. **Inline Mode** — выключен.
4. **Group Privacy** — если бот должен отвечать в группах без упоминания, выключить privacy mode и пере-добавить бота в группу.

## Безопасность

- API-ключи пользователей в БД только в зашифрованном виде: `base64(iv || ciphertext)` на AES-256-GCM, ключ шифрования — SHA-256 от `MASTER_SECRET` в `config.js`.
- Дамп БД без кода ключи не раскрывает. **Смена `MASTER_SECRET` делает все сохранённые ключи нечитаемыми** — пользователям придётся ввести их заново.
- Сообщение с ключом бот удаляет сразу после получения; ключ не печатается в логи и не возвращается в чат.
- `MASTER_SECRET`, `AI_API_KEY` (seed админа) лежат в `config.js` — он в `.gitignore`. Файл попадает в задеплоенные модули, поэтому при утечке ключ нужно перевыпустить.

## Ограничения

- Telegram rich messages: до 32 768 символов и до 500 блоков.
- Guest Mode даёт ровно один ответ на упоминание и не даёт доступа к истории чата.
- Стриминг драфтов работает только в приватных чатах — это ограничение Bot API.
- Проверка подписки требует, чтобы бот был админом канала.
